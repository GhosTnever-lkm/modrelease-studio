Что проверяет

Одна повторяемая проверка перед публикацией вместо ручного просмотра каждого файла. Сканер локальный: исходники никуда не отправляются.

Структуру и архив

  • опасные и дублирующиеся пути;
  • конфликты регистра и Unicode-имён;
  • лишние, слишком крупные и служебные файлы.

Содержимое и метаданные

  • распространённые API-ключи и токены;
  • поля descriptor.mod и YAML-локализации;
  • release notes и версию сборки.

Изменения и CI

  • сравнение двух сборок и SHA-256;
  • отчёты Markdown, JSON и SARIF 2.1.0;
  • GitHub Action для автоматического preflight.

Три типовых сценария

01 · ПЕРВЫЙ РЕЛИЗ

Перед загрузкой мода

Проверь папку, найди лишнюю вложенность, пропущенный файл или ошибку в метаданных и просмотри понятный отчёт.

02 · СБОРКА

Перед обновлением модпака

Просканируй ZIP-файлы единым способом и сравни новую сборку с предыдущей, чтобы заметить неожиданные изменения.

03 · CI

На каждом pull request

Подключи ModRelease Gate v1.0.58: проверка и отчёты появятся рядом с изменениями.

Быстрый старт

Нужен Python 3.11 или новее. Для установки используй виртуальное окружение; ниже закреплена актуальная версия.

python -m venv .venv
# Windows: .venv\Scripts\Activate.ps1
# macOS / Linux: source .venv/bin/activate
python -m pip install "modrelease-studio @ git+https://github.com/GhosTnever-lkm/modrelease-studio.git@v0.3.74"
modrelease scan ./my-mod --md-out release-report.md --json-out release-report.json
modrelease compare ./previous-build ./candidate-build

SARIF можно отправить в GitHub Code Scanning отдельным workflow-шагом. Для этого в вашем workflow потребуется разрешение security-events: write; сам сканер ничего не загружает.
