# Contributing

Thanks for helping make mod releases safer and easier to inspect.

1. Open an issue for a sizeable rule or format change so the expected behavior can be discussed.
2. Keep checks conservative and explain each finding in plain language.
3. Never include real credentials, private mod assets, or copyrighted game files in examples.
4. Run `python -m unittest discover -s tests -v` and include a short reproduction or fake-only sample fixture with a change.
5. Keep output deterministic and avoid adding network calls to the scanner.

By submitting a contribution, you agree that it may be distributed under this repository's MIT license.
